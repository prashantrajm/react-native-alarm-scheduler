API reference

Official method reference

Use this page in order. It starts with permissions, then scheduling, then native alarm state reconciliation, and ends with cleanup, Android Clock intents, and event listeners.

Quickstart

Import the default native module object and call methods directly. Event listeners are attached from the same object. 

import ExpoAlarm from 'react-native-alarm-scheduler';

const permissions = await ExpoAlarm.requestPermissionsAsync();

if (permissions.canScheduleExactAlarms) {
  await ExpoAlarm.scheduleAlarmAsync({
    id: '00000000-0000-4000-8000-000000000001',
    hour: 7,
    minute: 30,
    title: 'Morning alarm'
  });
}

Shared Types

These types are referenced by multiple methods below. Weekdays use ISO numbering: Monday is 1, Sunday is 7. 

type AlarmWeekday = 1 | 2 | 3 | 4 | 5 | 6 | 7;

type AlarmMetadataValue = string | number | boolean;
type AlarmMetadata = Record<string, AlarmMetadataValue>;

type AlarmAuthorizationStatus =
  | 'authorized'
  | 'denied'
  | 'notDetermined'
  | 'unavailable'
  | 'unknown';

Methods

The methods are ordered by a typical alarm lifecycle: capability check, scheduling, runtime reconciliation, completion, and cleanup.

1

getPermissionsAsync()

Read the current native alarm capability and authorization state.

const permissions = await ExpoAlarm.getPermissionsAsync();

Returns

type AlarmPermissionResponse = {
  platform: 'android' | 'ios';
  status: AlarmAuthorizationStatus;
  canScheduleExactAlarms: boolean;
  canOpenSettings: boolean;
  canUseFullScreenIntent?: boolean;
  canPostNotifications?: boolean;
};
Platform behavior

Android reports exact alarm capability. iOS returns authorized only when AlarmKit is available and the app has authorization.

canUseFullScreenIntent is the Android 14+ grant for taking over a locked screen; without it the alarm still rings but only as a heads-up notification. Both extra fields are true on older Android versions and on iOS.

2

requestPermissionsAsync()

Request or open the native permission surface where possible.

const permissions = await ExpoAlarm.requestPermissionsAsync();

Returns

Promise<AlarmPermissionResponse>

Platform behavior

On Android 12+, this can open exact alarm settings. On iOS 26+, this requests AlarmKit authorization.

3

openAlarmSettingsAsync()

Open the relevant app or alarm settings screen.

const opened = await ExpoAlarm.openAlarmSettingsAsync();

Returns

Promise<boolean>

4

openFullScreenIntentSettingsAsync()

Open the Android 14+ full-screen notification settings screen.

const permissions = await ExpoAlarm.getPermissionsAsync();

if (permissions.canUseFullScreenIntent === false) {
  await ExpoAlarm.openFullScreenIntentSettingsAsync();
}

Returns

Promise<boolean>

Platform behavior

Returns false on Android 13 and older, on iOS, on web, and when no matching settings activity exists.

5

scheduleAlarmAsync(alarm)

Schedule an app-owned native alarm.

const scheduled = await ExpoAlarm.scheduleAlarmAsync({
  id: '00000000-0000-4000-8000-000000000001',
  hour: 7,
  minute: 30,
  title: 'Morning alarm',
  weekdays: [1, 2, 3, 4, 5],
  ios: {
    alertTitle: 'Morning alarm',
    stopButtonTitle: 'Open',
    secondaryButtonTitle: 'Open',
    stopIntentBehavior: 'rescheduleImmediate',
    secondaryButtonBehavior: 'openApp',
    soundName: 'bollywood-alarm.mp3',
    metadata: {
      route: 'alarm-detail'
    }
  },
  android: {
    launchUri: 'myapp://alarm-detail',
    maxRingDurationSeconds: 0
  }
});

Input

type AlarmScheduleInput = {
  id?: string;
  hour: number;
  minute: number;
  title?: string;
  weekdays?: AlarmWeekday[];
  timestamp?: number;
  showUi?: boolean;
  ios?: IosAlarmOptions;
  android?: AndroidAlarmOptions;
};

type IosAlarmOptions = {
  metadata?: AlarmMetadata;
  alertTitle?: string;
  alertActionMode?: 'default' | 'openMissionOnly';
  stopButtonTitle?: string;
  secondaryButtonTitle?: string;
  countdownTitle?: string;
  stopIntentBehavior?: 'recordOnly' | 'openApp' | 'rescheduleImmediate';
  secondaryButtonBehavior?: 'openApp' | 'recordOnly' | 'none';
  soundName?: string;
};

type AndroidAlarmOptions = {
  metadata?: AlarmMetadata;
  alertTitle?: string;
  alertBody?: string;
  alertActionMode?: 'default' | 'openMissionOnly';
  stopButtonTitle?: string;
  secondaryButtonTitle?: string;
  stopIntentBehavior?: 'recordOnly' | 'openApp' | 'rescheduleImmediate';
  secondaryButtonBehavior?: 'openApp' | 'recordOnly' | 'none';
  soundName?: string;
  soundUri?: string;
  vibrate?: boolean;
  enforceVolume?: boolean;
  restoreVolume?: boolean;
  volume?: number;
  fullScreen?: boolean;
  fullScreenTarget?: 'native' | 'app';
  launchUri?: string;
  maxRingDurationSeconds?: number;
  backupDelaySeconds?: number;
};
Android inherits the iOS options

Every android field that means the same thing as an ios field falls back to it when omitted: metadata, alertTitle, alertActionMode, stopButtonTitle, secondaryButtonTitle, stopIntentBehavior, secondaryButtonBehavior and soundName. An app written against the AlarmKit flow behaves the same on Android without passing an android block at all.

alertActionMode: 'openMissionOnly' is absolute on Android: the package owns the ringing screen, so there is no stop button and the notification cannot be swiped away. The alarm rings until completeNativeAlarmAsync() or maxRingDurationSeconds.

Returns

type ScheduledAlarm = {
  id: string;
  hour: number;
  minute: number;
  title: string;
  weekdays: AlarmWeekday[];
  timestamp: number;
  platform: 'android' | 'ios';
  metadata?: AlarmMetadata;
};
Important constraints

hour uses 24-hour time. minute must be 0-59. Android accepts any string id. iOS AlarmKit requires a UUID string when you provide an id.

cancelAlarmAsync(id)

Cancel an app-owned alarm by id.

const removed = await ExpoAlarm.cancelAlarmAsync(alarmId);

Returns

Promise<boolean>

Cleanup

For iOS completion-gated flows, call completeNativeAlarmAsync(alarmId) before or alongside cancellation so native retry state is also cleared.

8

getCurrentAlarmContextAsync()

Read the active alarm context for launch or resume routing.

const context = await ExpoAlarm.getCurrentAlarmContextAsync();

if (context?.state === 'alerting' || context?.state === 'countdown') {
  const alarmId = context.metadata?.alarmId?.toString() ?? context.id;
}

Returns

type AlarmContext = {
  id: string;
  metadata?: AlarmMetadata;
  state?: 'scheduled' | 'alerting' | 'countdown' | 'paused';
  nativeAlarmId?: string;
};

If the active native alarm is a deterministic backup timer, id remains the original logical alarm id and nativeAlarmId contains the backup UUID.

On Android this returns the currently ringing alarm, falling back to a one-shot alarm that fired within the last hour and was never completed. On web it returns null.

9

getPendingNativeAlarmHandoffAsync()

Read the latest durable native alarm handoff.

const handoff = await ExpoAlarm.getPendingNativeAlarmHandoffAsync();

if (handoff?.action === 'nativeStop' || handoff?.action === 'secondaryOpen') {
  await ExpoAlarm.clearPendingNativeAlarmHandoffAsync();
  // Navigate using handoff.alarmId.
}

Returns

Promise<AlarmAction | null>

Why this exists

Native code writes this slot before JavaScript listeners are active, making it the right source for cold-start and app-resume routing. On iOS the AlarmKit App Intent writes it when the user presses a button; on Android it is written the moment the alarm starts ringing.

clearPendingNativeAlarmHandoffAsync()

Clear the durable native handoff slot after consuming it.

await ExpoAlarm.clearPendingNativeAlarmHandoffAsync();

13

scheduleNativeAlarmBackupAsync(alarmId, delaySeconds?)

Schedule a deterministic native backup alarm.

const backup = await ExpoAlarm.scheduleNativeAlarmBackupAsync(
  alarmId,
  0.1
);

Returns

type NativeAlarmBackupResult = {
  alarmId: string;
  backupAlarmId: string;
  scheduled: boolean;
  scheduledFor?: number;
  delaySeconds: number;
};

The backup id is deterministic for the primary alarm id. Calling this repeatedly cancels and replaces the same backup timer. iOS uses an AlarmKit timer; Android uses an exact setAlarmClock.

14

cancelNativeAlarmBackupAsync(alarmId)

Cancel the deterministic backup alarm for a logical alarm id.

const removed = await ExpoAlarm.cancelNativeAlarmBackupAsync(alarmId);

Returns

Promise<boolean>

15

completeNativeAlarmAsync(alarmId)

Mark a native alarm flow complete and clear retry state.

await ExpoAlarm.completeNativeAlarmAsync(alarmId);
await ExpoAlarm.cancelAlarmAsync(alarmId);

Returns

Promise<void>

Cleanup behavior

This marks the id complete for rescheduleImmediate, cancels deterministic backup alarms, removes legacy retry ids, and clears action records for that alarm.

On Android this is also what silences the ringing service, so it is mandatory rather than advisory: with alertActionMode: 'openMissionOnly' the alarm keeps playing until this call lands.

16

resetNativeAlarmCompletionAsync(alarmId)

Allow native retry scheduling again for a previously completed id.

await ExpoAlarm.resetNativeAlarmCompletionAsync(alarmId);

Returns

Promise<void>

clearBypassAsync(alarmId) is an older alias for the same completion-marker reset behavior.

17

getNativeAlarmDebugStateAsync(alarmId)

Inspect AlarmKit presentation, handoff, and retry state.

const debug = await ExpoAlarm.getNativeAlarmDebugStateAsync(alarmId);

console.log(debug.intentDebugCounts);
console.log(debug.pendingHandoff);
console.log(debug.activeRetryAlarmIds);

Returns

type NativeAlarmDebugState = {
  alarmId: string;
  isComplete: boolean;
  activeRetryAlarmIds: string[];
  pendingActions: AlarmAction[];
  pendingHandoff?: AlarmAction | null;
  intentDebugCounts?: Record<string, number>;
  currentContext: AlarmContext | null;
  alertActionMode?: 'default' | 'openMissionOnly';
  stopButtonIncluded?: boolean;
  secondaryButtonIncluded?: boolean;
  secondaryButtonBehavior?: 'openApp' | 'recordOnly' | 'none';
  stopIntentBehavior?: 'recordOnly' | 'openApp' | 'rescheduleImmediate';
  alertInitializer?:
    | 'secondaryOnly'
    | 'legacyStopButton'
    | 'androidRingService';
  runtimeSupportsSecondaryOnlyAlert?: boolean;
  sound?: 'default' | 'named';
  soundName?: string;
  isRinging?: boolean;
  isScheduled?: boolean;
  canUseFullScreenIntent?: boolean;
  canScheduleExactAlarms?: boolean;
};

On Android alertInitializer is always androidRingService, and isRinging, isScheduled, canUseFullScreenIntent and canScheduleExactAlarms describe the live state of the ringing service and the grants it depends on.

18

Android Clock Methods

Use system Clock intents on Android where supported.

setSystemAlarmAsync(alarm)

const opened = await ExpoAlarm.setSystemAlarmAsync({
  hour: 7,
  minute: 30,
  title: 'Morning alarm',
  weekdays: [1, 2, 3, 4, 5],
  showUi: true
});

Android sends AlarmClock.ACTION_SET_ALARM. iOS does not expose a public API for creating alarms in the system Clock app.

openSystemAlarmAppAsync()

const opened = await ExpoAlarm.openSystemAlarmAppAsync();

Opens the Android system Clock alarm screen when a compatible activity exists. iOS uses a best-effort Clock URL and may return false.

19

Events

Subscribe to foreground native alarm events.

const triggeredSub = ExpoAlarm.addListener(
  'onAlarmTriggered',
  (alarm) => {
    console.log(alarm);
  }
);

const actionSub = ExpoAlarm.addListener(
  'onAlarmAction',
  (action) => {
    console.log(action);
  }
);

const stateSub = ExpoAlarm.addListener(
  'onAlarmStateChange',
  (event) => {
    console.log(event);
  }
);

triggeredSub.remove();
actionSub.remove();
stateSub.remove();
Reconcile after launch

Foreground listeners are best effort. Apps should also reconcile from the async getters after launch or resume.
